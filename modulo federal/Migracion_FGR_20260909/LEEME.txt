ALCANCE Y DECISION DEL USUARIO

Se conservan los 115 pares de delitos con identificador repetido. No se eliminan,
no se renombran y no se duplican victimas para completar reglas nuevas.
Se importan todos los 58,523 registros de carpetas, 58,638 de delitos y 65,366
victimas. Las relaciones se conservan mediante pk_ci y pk_del originales.
Las claves autoincrementales de SQL Server son nuevas; los identificadores FGR
permanecen iguales. Los conteos y relaciones se verifican antes del COMMIT.
Los tres historicos estaban vacios: no se inventan versiones historicas.
La migracion no invoca validadores de carga ni cambia reglas de la API o el front.
Las nuevas cargas siguen pasando por las validaciones actuales.
Una futura actualizacion de los cortes historicos seguira usando el flujo actual;
este paquete no agrega excepciones de validacion a ese flujo.

Solo se inserta en tablas Federal. No se modifica el usuario ni sus permisos.
FGRX26011400 debe corresponder al usuario activo 68, nacional (entidad NULL).
Los envios, carpetas, delitos y victimas se atribuyen a ese usuario.
No se modifica mensual, semanal, repositorios, origen MariaDB ni archivos de publicacion.

El respaldo de tbl_envios_aux no tiene filas. Los ocho envios se reconstruyen a
partir de codigo_referencia, corte y conteos de los datos definitivos del legado.
Quedan CARGA_INICIAL / CONFIRMADO para que formen parte de los reportes confirmados.
Se mantiene fcha_insert en fecha_registro. La primera fcha_insert de cada envio
se usa como fecha_carga y fecha_validacion reconstruidas. Esto se documenta en
bitacora. fecha_confirmacion e id_usuario_confirmacion quedan NULL: no se inventa
una aprobacion administrativa ni se atribuye a un superusuario.

Se agrega UNA tabla de trazabilidad:
dbo.federal_migracion_fgr_20260909_mapa
Contiene 182,535 correspondencias (incluidos ocho envios), hash del respaldo,
fecha de migracion y login ejecutor. No eliminarla. Para CARPETA/DELITO/VICTIMA,
clave_origen es la PK original; para CARGA es codigo_referencia.
La bitacora de cada envio registra el evento de migracion a la fecha real de ejecucion.

CONVERSIONES NECESARIAS PARA EL ESQUEMA NUEVO

Los catalogos se buscan por clave; no se supone que su ID sea igual al del legado.
Municipio se resuelve por entidad + clave municipal. Una equivalencia requerida
inexistente, inactiva o ambigua detiene la operacion: no se omiten filas.
Los ceros del legado en catalogos opcionales de victimas representan ausencia de
clave y se convierten en NULL. Se conserva edad 999 como 999; edad/fecha vacias
se convierten en NULL. No se recalcula edad ni se corrigen reglas de negocio.
Las fechas/horas se convierten desde ISO y las cadenas se insertan como Unicode.
Codigo postal se conserva como texto; su FK puede quedar NULL si no hay equivalencia
para ese municipio, igual que en el repositorio de carga Federal.
Los nombres geograficos y otros campos que no tienen columna final propia permanecen
en 02_Datos_FGR.sql y en el respaldo original; el modelo final usa sus catalogos.
Los SQL no contienen los originales CSV/XLSX subidos al sistema viejo: no se crean
archivos falsos en UltimosArchivosFederal. Esa carpeta debe trasladarse por separado
si se requiere conservar las descargas de archivos originales.

con el respaldo: iguales, incluidos acentos, comillas, espacios y saltos de linea.
